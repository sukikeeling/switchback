# 架构决策记录（ADR）

> 借鉴 TRIO3.0-oss 的 ADR 体系：把"为什么这样设计"沉淀为可追溯的决策记录。
> 每条 ADR：背景 → 决策 → 理由 → 后果。

---

## ADR-001：不设自动恢复（No Auto-Resume）

**背景**：京张竞赛 5 轮"内容增强"（v8.2→v8.8）全部无效，70 是基准 84 是孤例。根因是 Agent 编排一旦开始就自动往下走，错误被一路放大，缺少"到站必停"的检查点。

**决策**：道岔状态机设三态（正线/侧线折返/入段检修），**被放行过、又被拉回检修态的任务禁止自动回正线**，必须经一次全新的放行式折返点复核。代码里以 `NoAutoResumeError` 强制。

**理由**：自动续行会放大错误。京张教训证明"克制 + 折返复核"比"自动续行"更接近高分。这是安全熔断的工程化表达。

**后果**：状态机首次放行（DEPOT→MAINLINE）允许走准入闸门；非首次的 DEPOT→MAINLINE 必须走 `re_enter_mainline(approval_checkpoint=PASS)`。测试 `test_no_auto_resume_from_depot` 永久守住此不变量。

## ADR-002：K 标用 SHA-256 哈希链而非数据库

**背景**：需要可审计的执行证据账本。可选：SQLite/JSON 数组/哈希链。

**决策**：内容寻址 SHA-256 哈希链，只追加不覆盖，篡改即断链。

**理由**：①零依赖（纯 stdlib `hashlib`）；②审计方持链可全量复核，不需要信任中心化 DB；③与 Git/IPFS/区块链的同构，语义清晰。数据库会引入依赖与信任假设。

**后果**：账本写入稍慢（每条重算哈希），但数据量小（案例级，非生产吞吐）。若未来需亿级吞吐，可换 Merkle 树但哈希链语义不变。

## ADR-003：弱隔离而非多模型强隔离

**背景**：三方复核（责任人/专业/公众）需要认知隔离，否则三票退化为"一个人的三种措辞"。

**决策**：当前为弱隔离（同模型不同 prompt 的角色分化），多模型强隔离为复赛目标。

**理由**：初赛以方案设计为主，零依赖可运行优先。AgentTeams 集群部署后，三角色可跑在不同 Worker 容器（真实隔离）。

**后果**：文档需诚实标注"当前弱隔离"（见 `docs/limitations.md`），不声称已是多模型强隔离。

## ADR-004：以 AgentTeams（Hiclaw）为设计基点

**背景**：赛道1 硬性要求多 Agent 协同必须以 AgentTeams 为基点。

**决策**：在 AgentTeams 的 Manager-Worker + Matrix 房间 + Higress 网关之上编排 6 个 Agent 身份。源码暂不 import AgentTeams SDK（初赛以方案为主），但映射文档与迁移契约保证迁移成本=协议适配而非重设计。

**理由**：AgentTeams 的"Matrix 房间人机可见可干预"正是折返点人机监理的天然基础设施。凭证透传模型与协议的安全边界一致。

**后果**：`docs/agentteams-mapping.md` 给出逐点映射；`docs/mcp-integration.md` 给出 Skill→MCP 迁移契约；诚实标注"当前为文档层，集群部署为复赛目标"。

## ADR-005：Skill 用 Python 函数 + SkillSpec 而非 SKILL.md 包

**背景**：六大 Skill 需可执行。可选：纯函数/可安装 SKILL.md 包/MCP tool。

**决策**：初赛用 Python 函数 + `SkillSpec` 机器可读声明；SKILL.md 标准包格式与 MCP 迁移为后续。

**理由**：①零依赖可运行优先；②`SkillSpec` 已含赛道要求的全部字段（名称/用途/输入输出/调用条件/依赖/失败处理/安全边界/复用价值）；③输入输出为 JSON 契约，迁移 MCP 只需包 transport。

**后果**：`docs/limitations.md` 标注落差；`docs/skills/` 补 SKILL.md 标准格式作为迁移目标。

## ADR-006：案例用剧本重放 + `--live` 核验而非纯拉 API

**背景**：京张 84 分案例需展示"真实任务闭环"。可选：纯剧本/纯拉 API/剧本+核验。

**决策**：剧本重放（确定性可复现）+ `--live` 模式用 GitHub API 验证 PR 真实存在。

**理由**：纯剧本不可信（审查报告 C 项指出了）；纯拉 API 不确定（限流/网络/评审 API 不公开）。剧本保证可复现，`--live` 保证真实性，两者互补。

**后果**：`replay jingzhang` 默认剧本（离线可跑），`--live` 联网核验 PR 存在性与合并状态。
